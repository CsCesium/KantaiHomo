# Calendar Kit 备用提醒

当前新登记的远征、时间点、明石维修及野埼给粮提醒使用 Calendar Kit，避免设备代理提醒额度为 0（1700002）时全部失败。此前已登记的代理提醒继续保留，并按原业务生命周期撤销，不同时创建同组日历提醒。

- 设置 → 日常提醒 → **授权日历并登记**：申请 READ_CALENDAR / WRITE_CALENDAR，建立本应用独立的本地“舰队提醒”日历；只在用户操作时弹出授权框。授权拒绝后不写入日程。
- 新日程以提醒发生时间为开始时间，`reminderTime: [0]`。演习两条每日重复，月度提醒保持未来 11 个周期；野埼 15/30 分钟分别登记。退出应用不删除日程。
- 通知由系统日历发送，声音、振动与显示样式遵循系统日历设置，应用无法保证日历通知无振动。时间点提醒不发应用 Toast，挂机计时保留每阶段一次的应用 Toast。
- `identifier` 保存应用标识、通知 ID 和业务 groupId；日程正文仅为用户可读内容。读取系统日历即可恢复，创建后立即退出也不会因本地索引未保存而重复创建。
- 各模块仍按 groupId 对账；关闭对应开关、编成或远征变化时清理对应日程。仅操作专属日历中拥有应用标识的日程，不删除其他日程或日历。撤销权限后无法清理，恢复授权后重试。
- Calendar Kit 的可选参数必须真正省略。全量查询使用 `getEvents()`，不能使用 `getEvents(undefined, keys)`；后者在真机原生桥接中报 `401 type error`。默认查询不含 recurrenceRule，演习的每日重复信息由业务组标识恢复。
- 取消时负数 ID 表示日历日程 `-(eventId + 1)`，非负数 ID 表示旧代理提醒；两者使用各自后端清理。

测试：`node scripts/test-calendar-reminders.cjs [typescript 路径]`，以及现有 expedition-alerts、refresh-reminders、harbor-mvp 测试。

真机验收：授权、登记、重启不重复、关闭开关删除，以及关闭应用后日历实际到点通知。成功写入日程不等于已验证通知投递。
