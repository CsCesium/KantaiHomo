# 明石维修 / 野埼给粮计时

- 设置 → 日常提醒提供开关，默认开启，键为 `alerts.harbor.enabled`。
- 按本次需求，仅识别旗舰为明石、明石改、野埼、野埼改的舰队。维修门槛 20 分钟；给粮在 15 分钟提醒后，将显示目标延长到本轮第 30 分钟，再提醒一次，连续挂机不再追加 45 分钟提醒。同类功能的舰队共享游戏计时。
- 到点表示“可回母港结算”，不修改本地 HP 或士气，也不宣称服务器已完成恢复。计时从首次观察到编成开始估算；其他终端的编成操作无法在发生时获知。
- 明石检查自身中破限制、入渠、可修理目标及修理设施覆盖范围（自身基础两舰，每个装备图鉴 ID 86 增加一舰）。本次未扩展朝日组合维修规则。
- 野埼检查满燃弹、损伤低于小破、cond ≥ 30，以及有未入渠且 cond < 54 的随伴舰。出击、演习、远征中的对应舰队不显示挂机提醒。
- 普通编成变更重置对应的共享计时，编成预设和随伴一键解除保留计时；提前回港不重置，达到门槛后回港进入下一轮。
- 每轮维修、给粮的 15/30 分钟阶段各最多弹出一次 Toast，遵循现有 Toast 总开关；不调用振动。超过 30 分钟才恢复前台时，只补最新阶段的 Toast。系统日历提醒使用不振动的 CONTENT_INFORMATION 通道、普通通知模式；给粮两阶段提前登记，应用退出后仍保留。用户修改系统通道后，以系统设置为准。
- 开关关闭或舰队不再满足条件时撤销对应提醒；账号独立保存起点和提醒状态到 `alerts.harbor.clock.<memberId>`。启动后等到新鲜母港数据再确认计时，避免仅凭旧编成发通知。
- 常驻通知 ID 100 标题优先显示挂机功能，正文固定三行，分别展示第 2、3、4 舰队的远征或空闲状态，挂机详情不占正文。没有有效挂机计时后，恢复 `归来：HH:mm:ss「远征名」`。时间放在远征名之前，折叠和展开标题保持一致。
- 按功能和阶段而非每支舰队登记，最多三条挂机提醒。周期提醒滚动登记 11 个月（22 条月度 + 2 条演习），为两阶段给粮和远征预留容量，符合系统 30 条额度。登记暂时失败时应用运行期间重试，到点可用普通系统通知兜底。

规则参考（2026-09-18）：[明石泊地维修](https://wikiwiki.jp/kancolle/明石)、[舰艇修理设施](https://wikiwiki.jp/kancolle/艦艇修理施設)、[野埼给粮](https://wikiwiki.jp/kancolle/野埼)。

验证：`node scripts/test-harbor-mvp.cjs [typescript 路径]`、`node scripts/test-expedition-alerts.cjs [typescript 路径]`、`node scripts/test-refresh-reminders.cjs [typescript 路径]`。真机需验证三行远征正文、系统通知通道不振动、关闭应用后两阶段给粮提醒、20/15/30 分钟回港结算和设备时钟变更。
